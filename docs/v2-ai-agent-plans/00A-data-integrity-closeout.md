# 阶段 0A：数据完整性与权限核对收尾

## 阶段定位

本阶段当前是“收尾审核”，不是从头实现。工作区已经包含稳定题目 ID、事务化、字段链路、掌握度纯函数及检查脚本等未提交改动。执行 agent 必须先审 diff，再只补缺口。

- 主计划依据：5.0、5.0.1、阶段 0A、5.2。
- 前置依赖：无；最终完成依赖阶段 0B 提供正式 vitest 与临时 PostgreSQL 夹具。
- 后继解锁：阶段 1～5。

## 执行范围

1. 审核 A1～A4：
   - 小节题目按完整 UUID 做增量 diff。
   - 更新题目时验证其属于当前小节。
   - `PUT /admin/lessons/:id` 只按小节解析。
   - `createLesson`、`updateLesson` 的小节与题目写入处于单个 Prisma 事务，错误向调用方返回。
2. 审核前置项 C：
   - `knowledge`、`analysis`、`source` 的前后端录入和更新链路完整。
   - 手工题固定 `source='static'`，编辑既有 AI 题不覆盖其来源。
3. 审核前置项 D：
   - 掌握度规则是纯函数，边界值清楚。
   - 本阶段不得接入 `mastery_level` 数据库写入。
4. 完成未登录、普通用户、管理员对四组管理接口的 401/403/200 回归，并记录到验收清单。
5. 阶段 0B 就绪后，把现有临时检查纳入正式 vitest/集成测试入口，补跑集成测试 ①。

## 禁止事项

- 不重构全局短 ID 方案，不改变前台 URL。
- 不增加新的角色中间件。
- 不提前增加 `review_status`、RAG 索引或掌握度写入。
- 不清理或重排同期 Radix UI 改造。
- 不以删除再重建题目替代增量更新。

## 必须验证

- 同一小节连续保存两次，所有既有题目 UUID 不变。
- 删除一道题不改变其余题目的 UUID 与关联。
- 非法题目使 create/update 整体回滚，不产生半成品小节。
- 跨小节伪造题目 UUID 返回错误且目标题未被改写。
- `answer`、`code_submissions` 关联不因编辑小节断开。
- 三个题目字段在新建、编辑后均为预期值。
- 掌握度纯函数覆盖 0～100、提示扣减和异常输入边界。

建议执行：

```powershell
cd backend
pnpm run build
pnpm run check:mastery
pnpm run check:0a-db

cd ..\frontend
pnpm run check
pnpm run build
```

`check:0a-db` 只能连接名称明确的临时测试库，并继续保留显式开关与数据库名双重保护。禁止对开发库或生产库运行破坏性夹具。

## 交付物

- 必要的最小代码修正。
- 正式的纯函数测试与集成测试 ①（若阶段 0B 已提供框架）。
- 权限三态回归记录。
- 阶段 0A 交接报告，特别说明哪些改动是原有、哪些由本 agent 补充。

## 审核门禁

- A/C/D 所有标准有代码和测试证据。
- 集成测试 ①在独立临时库重复执行通过。
- `mastery_level` 尚无新数据库写入点。
- 不影响现有小节管理和做题关联。
- 阶段 0B 未完成时，最高只能判为“条件通过”。
