# 阶段 6：工程治理、评估与发布收尾

## 阶段定位

把已完成的 AI 能力变成可观测、可回归、可运维、可作发布判断的系统。本阶段不再扩展产品能力。

- 主计划依据：3.5、阶段 6、5.1、5.2、第 7 节。
- 前置依赖：阶段 1～5 审核通过。
- 发布依赖：阶段 0C 生产迁移完成。

## 执行范围

1. `ai_call_logs`：
   - 记录 trace、scene、node、模型、Prompt 版本、token、估算成本、耗时、重试、降级、状态和错误码。
   - 默认不保存原始 Prompt。
2. `ai_feedback_events`：
   - 记录题目采用/编辑/拒绝、推荐曝光/点击/完成、用户反馈、申诉和复核结果。
3. 扩展限流到 chat 等高成本接口，并接入 Redis 与告警。
4. 完善索引补偿：
   - 定时调度。
   - generation 冲突和悬挂任务统计。
   - 可重复执行的报告与告警。
5. checkpoint 生命周期：
   - 只清理“已确认完成且超过保留期”的线程。
   - 提供 dry-run、批量上限、审计日志和重复执行能力。
6. 指标与告警：
   - 最小 SQL/脚本报告或看板。
   - 质量、可靠性、性能、成本、降级和人工接管。
7. 冻结模型、Prompt、检索参数和数据集版本，运行完整离线回归。
8. 产出：
   - `docs/CodeStory_V2.0_验收清单.md`
   - `docs/CodeStory_V2.0_评估报告.md`
9. 复核所有“无沙箱评阅不等于严格判题”的产品文案。

## 告警与性能门槛

- 5 分钟窗口任务成功率低于 95% 告警。
- P95 超过对应场景基线两倍告警。
- 当日成本达到预算 80% 告警，100% 时限制非必要高成本任务。
- 自由 Chat 首 Token P95 ≤ 3s。
- 非流式 AI 任务 P95 ≤ 30s。
- 引导式学习单独计量，不混入自由 Chat。

如环境确实无法满足性能门槛，必须记录实测基线、原因和经用户确认的新预算，不能直接删除指标。

## 禁止事项

- 不借收尾重构所有 service。
- 不引入复杂可观测平台或消息队列。
- 不记录 Token、验证码、联系方式、密钥或完整敏感 Prompt。
- 不只按时间删除 checkpoint。
- 不为提高报告分数删除失败样本或只重跑失败项。

## 必须验证

- 任一 AI 请求可用 trace ID 还原入口、检索/工具、模型、重试/降级、业务结果和反馈。
- 关键 AI 场景有调用日志，且敏感信息扫描无命中。
- 限流和三类告警可通过可控方式触发。
- 索引补偿与 checkpoint 清理脚本支持 dry-run、重复执行和进行中任务保护。
- 完整评测集全量运行；报告至少列 10 个失败案例并分类。
- 所有阶段手工回归清单可逐条执行。
- 在所有硬门槛满足前，`AI_GRAPH_ENABLED` 保持默认关闭。

## 交付物

- migration、埋点薄封装、限流扩展、维护脚本和报告脚本。
- 完整验收清单与评估报告。
- 版本冻结清单和发布建议：`可发布`、`有条件发布` 或 `不可发布`。
- 未达标项必须有负责人、影响、临时控制和复验方法。

## 审核门禁

- 日志数据足以排障但不泄露敏感内容。
- 指标能从原始记录重复计算。
- 清理/补偿脚本有安全边界和 dry-run。
- 报告口径与主计划 5.1 完全一致。
- 0C 未通过时只能给开发完成结论，不能给生产发布结论。
