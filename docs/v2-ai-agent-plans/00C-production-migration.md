# 阶段 0C：生产数据库迁移与回滚演练

## 阶段定位

本阶段当前延期。它不阻塞本地开发，但阻塞任何 V2.0 能力上线。只有用户明确启动目标服务器导入和切换后，才允许执行生产写操作。

- 主计划依据：阶段 0C、第 4 节 checkpoint 运维口径、第 7 节数据库迁移风险。
- 前置依赖：本地迁移准备已完成；生产新增 Schema 以待发布版本 migration 为准。
- 后继解锁：生产发布。

## 已知基线

- 最终迁移归档：`codestory_backup/codestory_db_migrated_20260727.dump`。
- 主计划记录的 SHA-256：
  `69E2517415782F70935D1D5C12C64A70217FC92A240ED5B5F402FE014780628B`。
- 目标数据库镜像：`pgvector/pgvector:0.8.2-pg16-bookworm`。
- 生产数据卷：外部卷 `codestory_postgres_data`。
- 生产归档和凭据不得提交、外发或出现在日志中。

执行前必须重新读取主计划 0C 的最新状态，不能只依赖本任务书中的历史基线。

## 执行闸门

在进行任何目标服务器变更前，执行 agent 必须确认并在交接中记录：

1. 用户已明确授权本次生产迁移与维护窗口。
2. 目标主机、Compose 项目和外部卷的精确名称。
3. 当前公网入口是否关闭、源库是否仍停写。
4. dump 校验和、大小和 `pg_restore --list` 结果。
5. 管理员账号与应用账号分离；真实凭据只从受控环境读取。
6. 本次待发布 migration 清单和 checkpoint 表是否纳入备份。

任一项不明确时只允许做只读检查和演练，不得猜测。

## 执行范围

1. 预创建外部卷，只启动 PostgreSQL/Redis，验证健康与网络隔离。
2. 管理员启用 vector 扩展；应用账号保持非超级用户并拥有业务 schema。
3. 对全新空库执行单事务原子恢复：
   - `--role` 指向应用账号。
   - `--no-owner --no-acl --exit-on-error --single-transaction`。
4. 对账 `_prisma_migrations`、实际 Schema、checksum 和状态，再决定是否 `migrate deploy`。
5. 独立执行 checkpointer setup，禁止通过应用启动隐式建表。
6. 恢复并验证历史 `/uploads/...` 和兼容副本。
7. 用浏览器实际 origin 配置 `NEXT_PUBLIC_*` 后重建前端。
8. 开放入口前完成数据库断言和关键业务回归。
9. 配置每日备份、保留策略、异地加密副本和月度恢复演练。
10. 切换完成后轮换旧库和历史环境凭据。

## 禁止事项

- 不对已有业务对象的非空目标库直接恢复。
- 不用 `migrate resolve` 掩盖迁移漂移。
- 不发布 PostgreSQL/Redis 端口。
- 不在验证完成前启动公网入口。
- 新库产生写入后，不把迁移 dump 当作无损回滚点。
- 不执行 `docker compose down -v` 或任何未解析目标的卷删除。

## 必须验证

- 关键表行数、序列、迁移记录、Schema 和 pgvector 版本正确。
- 登录、刷新 Token、课程浏览、历史图片、选择题、代码题、AI 降级通过。
- 应用账号能运行应用和 migration/checkpointer 所需 DDL，但不是超级用户。
- PostgreSQL/Redis 仅在内部数据网络。
- 从 dump 到隔离库的恢复演练成功。
- 每日备份已实际生成一份，本机保留策略和异地副本可核查。
- 首次月度演练的 RTO 有记录，初始 RPO 为 24 小时。

## 交付物

- 不含秘密的迁移执行记录和时间线。
- 迁移前后断言、业务回归、备份/恢复证据。
- 生产拓扑与部署文档的必要更新。
- 明确的切换点、首批新写入时间和此后可用的回滚方式。
- 凭据轮换完成确认，不包含凭据值。

## 审核门禁

- 所有生产步骤均有授权、精确目标和结果证据。
- 数据、uploads、checkpoint 和 migration history 均进入备份责任范围。
- 新入口只在完整验收后开放。
- 任一关键断言失败都应停止切换并废弃该次恢复结果，而不是现场修补生产数据。
