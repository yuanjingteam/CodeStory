# 阶段 2：AI 出题生成与独立题目管理

## 阶段定位

补齐 P0：管理员可从知识点生成结构化题目草稿，在独立管理页审核后发布。

- 主计划依据：3.1.3、3.6、阶段 2、5.3、5.1。
- 前置依赖：阶段 1 审核通过。
- 后继解锁：阶段 4。

## 执行范围

### 数据与后端

1. migration 增加：
   - `exercises.review_status`，仅允许 `draft/approved/rejected`。
   - `exercises.gen_metadata`。
   - 存量题默认/回填为 `approved`；AI 新题显式为 `draft`。
2. 实现 LCEL 出题链：
   - RAG 检索。
   - 候选生成。
   - 格式、答案存在性与难度自检。
   - 基于题目 embedding 的重复初筛。
   - zod 结构化输出；解析失败最多一次修复重试。
3. 题型严格限制为 `single_choice` 和 `code`。
4. 新增独立管理 service/route：
   - 生成、列表、详情、编辑、删除/软删。
   - 采用、编辑后采用、拒绝的条件状态更新。
   - 所有路由挂现有 `authMiddleware + requireAdmin`。
5. 学习端所有题目查询增加 `review_status='approved'`。
6. 出题接口使用 Redis 支持的分布式限流，错误可读。

### 前端

把 `exercises-manage` 占位页建成正式页面：

- 分页、课程/章节/小节/题型/难度/source/review_status 筛选。
- AI 生成表单与候选预览。
- 采用、编辑后采用、拒绝。
- `gen_metadata` 溯源面板。
- 待审队列和等待时长。
- 手工题增删改，含 `knowledge/analysis/source`。

沿用既有后台布局和 Neo-Brutalism 设计规范；保留 lessons-manage 内原有题目编辑区。

## 关键不变量

- AI 草稿绝不自动出现在学习端。
- 生成过程失败不产生半截数据；候选批次要么完整落草稿，要么不落。
- 管理编辑小节不能丢失题目的审核态和生成元数据。
- 审核状态更新使用条件更新，重复请求不可覆盖已经生效的结论。
- `gen_metadata` 保存 trace、模型、Prompt 版本、检索来源定位、参数与自检结果，不保存密钥或完整敏感 Prompt。

## 禁止事项

- 不实现 `fill`、`judge` 或即时发布。
- 不把出题链放入 LangGraph。
- 不复用学习端 `routes/exercises.ts` 承载管理能力。
- 不修改全局视觉语言或移除 lessons-manage 题目编辑。
- 不以客户端按钮禁用代替服务端并发、权限与限流。

## 必须验证

- 管理员生成至少一道字段完整的题目草稿。
- 未审核题在小节详情、题目列表和提交入口均不可见。
- 采用后可见，拒绝后不可见。
- 未登录/普通用户/管理员分别得到 401/403/成功。
- 超过限流阈值得到可读响应且不继续触发模型调用。
- 编辑所属小节后审核态和 `gen_metadata` 保留。
- 固定构造数据的 Schema 测试 100% 通过。
- 不少于 100 道候选题上达到主计划指标：
  - 首次结构化成功率 ≥ 90%。
  - 修复后成功率 ≥ 99%。
  - 最终失败率 ≤ 1%。
  - 每道有效候选平均模型调用次数 ≤ 1.3。
  - 人工复核答案正确率 ≥ 95%。
  - 人工确认重复率 ≤ 5%。

## 交付物

- migration、后端出题链、管理 API、学习端查询过滤。
- 完整 `exercises-manage` 页面及 API client/types。
- 限流配置和环境示例。
- Schema 测试、权限/审核/限流回归、出题评测报告。
- 如实现分成后端与前端两批，最终交接必须提供完整闭环证据，不能只交接口或静态页面。

## 审核门禁

- 迁移对存量题安全，AI 题默认 draft。
- 权限、资源归属、审核并发与限流均在服务端成立。
- 所有学习端读取路径都过滤未审核内容。
- 页面遵循项目设计规范且具备加载、空、错、禁用与移动端状态。
- 质量指标按正确分母计算，不能只统计成功返回的候选。
