## 1. 验收原则

V1 不验收完整 Agent 平台能力，只验收学习页里的核心闭环：

```text
进入小节
-> 与 AI 讨论当前知识点
-> 打开练习
-> 请求提示
-> 提交选择题并可选 AI 解释
-> 提交编程题并获得无沙箱 AI 评阅
-> 查看评分拆解和反馈
-> 刷新页面后恢复聊天历史
```

验收时重点确认三件事：

1. 功能能跑通。
2. 数据能保存和恢复。
3. 页面不把无沙箱 AI 评阅描述成真实运行代码或严格判题。

## 2. 验收前准备

### 2.1 服务准备

确认下面服务可用：

- PostgreSQL 数据库已连接到当前开发环境。
- 后端服务正常启动。
- 前端服务正常启动。
- AI 配置可用，或者可以临时制造 AI 失败场景。

### 2.2 基础检查

先执行基础类型和构建检查：

```powershell
cd backend
pnpm run build
```

```powershell
cd frontend
pnpm run typecheck
```

预期结果：

- 后端 TypeScript 构建通过。
- 前端类型检查通过。
- 没有新增阻塞性错误。

### 2.3 测试账号和测试数据

建议准备：

- 一个已登录学生账号。
- 一个包含小节正文的课程小节。
- 至少一道选择题。
- 至少一道编程题。
- 一道配置了管理员固定提示的练习。
- 一道没有配置管理员固定提示的练习。

## 8. 文案验收

### T16 无沙箱文案

操作：

1. 搜索前端页面和接口反馈中的相关文案。
2. 重点检查编程题按钮、结果弹窗、AI 反馈标题。
3. 检查前端营销文案是否宣传了 V1 未实现的 Agent 能力。

预期结果：

- 不出现误导性的"运行代码""真实测试通过""严格判题通过"。
- 可以出现"静态初评""提交评阅""AI 智能评阅""无沙箱 AI 评阅"。
- 文档中提到沙箱时，必须明确是 V1 暂不引入。
- 前端文案不得宣传"AI Agent""Agent 交互""Agent 陪伴"等 V1 未实现的 Agent 能力；应使用"AI 学习助手""AI 助手"等与 V1 实际功能匹配的表述。

推荐搜索：

```powershell
Get-ChildItem frontend\src,backend\src,docs -Recurse -File |
  Select-String -Pattern "运行代码|真实测试|严格判题|沙箱"
```

```powershell
# 检查 Agent 过度宣传（V1 未实现 Agent，文档中明确的不做项除外）
Get-ChildItem frontend\src -Recurse -File -Include *.ts,*.tsx |
  Select-String -Pattern "AI Agent|Agent 交互|Agent 陪伴|Agent交互"
```

## 10. 当前建议执行顺序

第一轮优先跑：

```text
T10 编程题正确答案
T11 编程题错误答案
T13 AI 评阅失败降级
T03 刷新后恢复历史消息
T09 选择题 AI 解释
```

原因：

- 编程题 AI 评阅是 V1 风险最高的链路。
- 刷新恢复能验证会话和消息记录是否真的生效。
- 选择题解释能验证 AI 只解释、不改判分。
