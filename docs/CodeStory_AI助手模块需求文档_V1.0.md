# CodeStory AI 助手模块需求文档

> 文档版本：V1.1  
> 文档状态：V1 核心范围收口版  
> 更新日期：2026-06-24  
> 适用对象：产品设计、前端、后端、AI 工程、测试

## 1. 文档目的

本文档定义 CodeStory AI 助手第一版需要实现的核心功能、业务规则、数据需求和验收标准。

V1 只服务一个目标：

```text
让用户在小节学习页中获得可对话、可提示、可解释、可评阅的 AI 学习辅助体验。
```

V1 不追求完整 Agent 平台，不引入真实代码沙箱，不引入 LangGraph，不做 RAG 和长期记忆。

## 2. V1 产品目标

AI 助手定位为“小节学习页里的编程学习导师”，不是通用聊天机器人。

V1 需要达到以下目标：

1. AI 能理解当前小节和当前练习。
2. 学生可以围绕当前学习内容与 AI 对话。
3. 学生写代码时，可以让 AI 分析当前编辑器代码。
4. 学生遇到困难时，可以逐级获取提示。
5. 选择题继续使用数据库答案判分，AI 只负责可选解释。
6. 编程题使用无沙箱 AI 评阅提供学习反馈。
7. 系统能够保存会话、消息、提示、代码提交和评分依据。

## 3. V1 必须实现的模块

| 编号 | 模块 | 核心作用 | 优先级 |
| --- | --- | --- | --- |
| V1-M01 | 小节 AI 对话 | 围绕当前小节和练习进行问答 | P0 |
| V1-M02 | 会话与消息记录 | 保存对话、提示和代码分析上下文 | P0 |
| V1-M03 | 三级提示 | 按等级提供逐步增强的帮助 | P0 |
| V1-M04 | 选择题 AI 解释 | 判分后解释正确和错误选项 | P1 |
| V1-M05 | 无沙箱 AI 编程题评阅 | 评价代码思路、质量和问题 | P0 |
| V1-M06 | AI 评分整合 | 展示功能分、质量分、提示扣分和最终分 | P0 |

## 4. V1 明确不做

以下能力不进入 V1：

- LangGraph 流程编排
- 真实代码执行沙箱
- 容器化判题服务
- 隐藏测试用例执行
- RAG、向量库、长期记忆
- token、耗时、失败率统计
- 接口限流
- 提交历史面板
- AI 评审失败后单独重试
- 管理员 AI 自动出题
- AI 自动修改或提交学生代码
- 由 AI 单独决定编程题严格正确或错误
- 项目级、多文件代码评审

这些能力可以作为 V2 或上线前增强项。

## 5. 模块一：小节 AI 对话

### 5.1 功能说明

学习者可以在小节学习页面与 AI 助手对话。

AI 回答时应理解：

- 当前课程名称
- 当前章节和小节
- 当前小节正文
- 当前练习题
- 当前编辑器代码
- 最近对话上下文
- 用户已使用的提示等级

### 5.2 基本功能

- 发送文本消息
- 流式展示 AI 回复
- 停止当前生成
- 重新发送失败消息
- 保存用户消息和 AI 消息
- 重新进入小节后查看历史消息
- 根据消息类型展示标签

### 5.3 快捷操作

V1 提供以下快捷入口：

- 解释知识点
- 给我提示
- 分析我的代码
- 分析练习
- 解释题目
- 总结本节

### 5.4 回答规则

- 优先围绕当前小节回答。
- 与课程无关的问题只做简短回应，并引导回当前学习内容。
- 不确定时应明确说明，不得编造课程内容。
- 优先引导学生思考，不直接代写完整答案。
- 不得将完整标准答案或隐藏测试发送给学生。

## 6. 模块二：会话与消息记录

### 6.1 AI 会话

每个用户在每个小节中拥有一个当前 AI 会话。

会话记录：

- 用户 ID
- 小节 ID
- 当前练习 ID
- 当前提示等级
- 必要上下文
- 最近活动时间

### 6.2 聊天消息

消息记录至少包含：

- 消息 ID
- 会话 ID
- 消息角色：用户、AI、系统
- 消息内容
- 消息类型
- 创建时间
- metadata

消息类型包括：

- `chat`：普通问答
- `hint`：提示
- `code_analysis`：代码分析
- `system`：系统消息

### 6.3 最近上下文策略

V1 不使用长期记忆和向量检索。

AI 调用时只使用有限最近上下文：

```text
当前小节正文
+ 当前练习信息
+ 当前编辑器代码
+ 最近普通问答
+ 最近提示
+ 最近代码分析
+ 当前用户问题
```

上下文应限制数量和长度，避免 Prompt 过长。

### 6.4 验收标准

- 刷新页面后聊天记录仍然存在。
- 不同用户之间不会读取到彼此消息。
- 不同小节之间的会话互不影响。
- 历史消息数量受到限制。
- 页面刷新不会重复调用 AI。

## 7. 模块三：三级提示

### 7.1 功能说明

学生不会作答或代码测试失败时，可以主动请求提示。

提示逐级增强，避免第一次请求就直接给出答案。

### 7.2 提示等级

| 等级 | 目标 | 允许内容 | 禁止内容 |
| --- | --- | --- | --- |
| Level 1 | 提供思考方向 | 相关概念、观察点、题目方向 | 关键代码、完整步骤 |
| Level 2 | 缩小问题范围 | 解题步骤、关键语法、错误范围 | 可直接提交的完整实现 |
| Level 3 | 提供解题脚手架 | 伪代码、局部关键表达式、函数结构 | 无解释的完整答案 |

### 7.3 提示来源

V1 允许两种提示来源：

1. 管理员预先配置的固定提示。
2. AI 根据题目和上下文生成的动态提示。

优先规则：

- 存在固定提示时优先使用固定提示。
- 固定提示不足时，再由 AI 生成对应等级提示。
- AI 生成提示不得超过当前提示等级。

### 7.4 提示扣分

V1 可沿用当前规则：

| 使用情况 | 建议扣分 |
| --- | ---: |
| 未使用提示 | 0 |
| 使用 Level 1 | 10 |
| 使用 Level 2 | 20 |
| 使用 Level 3 | 30 |

## 8. 模块四：选择题 AI 解释

### 8.1 功能说明

选择题继续使用数据库答案做确定性判分。

AI 只在用户主动点击“解释答案”后调用，用于解释：

- 正确选项为什么正确
- 用户选择为什么不合适
- 其他选项分别错在哪里
- 下一步学习建议

### 8.2 业务规则

- AI 不参与选择题正确性判断。
- AI 服务不可用时，选择题仍然可以正常提交。
- 数据库答案是选择题最终判定依据。
- AI 解释不得修改正确性和得分。

## 9. 模块五：无沙箱 AI 编程题评阅

### 9.1 功能说明

V1 不执行学生代码，不引入沙箱。

编程题评阅采用：

```text
学生代码
-> 静态初判
-> AI 结构化评阅
-> 分数、反馈、问题、建议
```

### 9.2 AI 评阅输入

AI 评阅输入包括：

- 题目要求
- 题目解析
- 参考答案
- 学生代码
- 编程语言
- 静态初判结果
- 已使用提示等级
- 固定 Rubric

### 9.3 AI 评阅输出

AI 应返回：

```json
{
  "isLikelyCorrect": true,
  "functionalScore": 62,
  "qualityScore": 24,
  "feedback": "整体思路基本正确，但字段约束还可以更严谨。",
  "strengths": ["使用了正确的查询结构"],
  "issues": ["WHERE 条件没有完全覆盖题目限制"],
  "suggestions": ["重新核对题目中的字段和筛选条件"],
  "needsManualReview": false
}
```

### 9.4 约束

- AI 评阅不等同于真实运行判题。
- AI 不得声称已经执行了学生代码。
- 分数必须限制在规定范围内。
- AI 调用失败时降级，不阻塞提交。
- 前端文案必须明确这是“AI 智能评阅”。

## 10. 模块六：AI 评分整合

### 10.1 功能说明

V1 需要把 AI 评阅结果、提示扣分和最终成绩展示给用户。

基础公式：

```text
最终分 = 功能分 + 质量分 - 提示扣分
```

### 10.2 展示内容

结果页应展示：

- 功能分
- 质量分
- 提示扣分
- 最终分
- AI 反馈
- 优点
- 问题
- 建议
- 是否需要人工复核

### 10.3 异常规则

- AI 失败时保留静态初判结果。
- AI 失败不得导致提交接口失败。
- AI 失败时前端展示清晰提示。
- 同一次提交不应重复计分。

## 11. 异常与降级

V1 需要区分以下 AI 错误：

| 错误码 | 含义 |
| --- | --- |
| `AI_REQUEST_INVALID` | 请求参数不合法 |
| `AI_CONTEXT_INVALID` | 当前小节或练习上下文异常 |
| `AI_CONFIG_MISSING` | AI 服务配置缺失 |
| `AI_TIMEOUT` | AI 响应超时 |
| `AI_RATE_LIMITED` | AI 请求过于频繁 |
| `AI_PROVIDER_ERROR` | 模型服务异常 |

页面需要：

- 显示清晰错误提示
- 支持重新发送
- 区分停止生成和服务失败
- 重试代码分析时保留原代码快照

## 12. V1 验收标准

### 12.1 小节 AI 对话

| 编号 | 验收条件 |
| --- | --- |
| AC-01 | 用户可以在小节页面发送消息并获得流式回复 |
| AC-02 | AI 能读取当前小节和当前练习上下文 |
| AC-03 | 刷新页面后可以恢复历史消息 |
| AC-04 | AI 不会在普通问答中直接泄露完整标准答案 |
| AC-05 | AI 失败时有明确提示并允许重试 |

### 12.2 三级提示

| 编号 | 验收条件 |
| --- | --- |
| AC-06 | 用户可以依次获取 Level 1、Level 2 和 Level 3 提示 |
| AC-07 | Level 1 和 Level 2 不包含完整可提交答案 |
| AC-08 | 系统能够记录已使用的提示等级 |
| AC-09 | 提示扣分能参与最终成绩计算 |

### 12.3 选择题

| 编号 | 验收条件 |
| --- | --- |
| AC-10 | 选择题继续通过数据库正确答案判分 |
| AC-11 | AI 服务不可用时选择题仍可正常提交 |
| AC-12 | AI 解释不会改变选择题得分 |

### 12.4 编程题 AI 评阅

| 编号 | 验收条件 |
| --- | --- |
| AC-13 | 编程题提交后能获得 AI 评阅反馈 |
| AC-14 | AI 评阅结果包含功能分、质量分和反馈 |
| AC-15 | AI 失败时提交接口仍然可用 |
| AC-16 | 页面明确说明这是无沙箱 AI 智能评阅 |

### 12.5 会话与记录

| 编号 | 验收条件 |
| --- | --- |
| AC-17 | 每条用户和 AI 消息能保存并恢复 |
| AC-18 | 消息类型能够区分普通问答、提示、代码分析和系统消息 |
| AC-19 | 最近上下文数量受控 |
| AC-20 | 刷新页面不会重复调用 AI |

## 13. V1 完成标志

当用户能完成下面流程时，V1 可以视为基本完成：

```text
进入小节
-> 与 AI 讨论当前知识点
-> 打开练习
-> 请求提示
-> 提交选择题并可选 AI 解释
-> 提交编程题并获得无沙箱 AI 评阅
-> 查看评分拆解和反馈
-> 刷新页面后恢复聊天历史
```

V1 不要求完成 LangGraph、沙箱、RAG、限流、可观测性和提交历史面板。
