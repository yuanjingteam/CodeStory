# CodeStory 前端设计规范

> **✅ 状态：当前有效**
>
> **最后核对：2026-07-21**
>
> 适用范围：`frontend/src/**` 中所有可见界面
>
> 设计方向：Neo-Brutalism（新粗野主义）

本文档是 CodeStory 前端视觉与交互实现的唯一执行标准。产品需求文档用于说明背景；发生细节差异时，以本文档和现有已上线组件为准。用户明确提出新的项目级设计方向时，应同步更新本文档。

## 1. 设计原则

- **直接清晰**：优先建立信息层级、阅读顺序和操作反馈，再增加装饰。
- **粗粝但有秩序**：使用明确边框、硬阴影和高对比色块，但保持统一的间距、对齐和比例。
- **继承现有语言**：新页面和组件应复用已有布局、颜色、边框及交互模式，不局部引入玻璃拟态、霓虹渐变等竞争风格。
- **功能优先**：装饰不能降低可读性、键盘操作、移动端适配或加载性能。
- **适度使用容器**：仅在需要表达分组或层级时使用卡片，避免把每段内容都包成独立卡片。

## 2. 视觉语言

### 2.1 边框与阴影

- 卡片、按钮、输入框、弹窗等交互或分组容器使用清晰的黑色实线边框，通常为 `border-2 border-black`；强调区域可使用 `border-4`。
- 使用向右下偏移的纯色硬阴影，不使用模糊外发光。常用形式为 `shadow-[4px_4px_0_0_rgba(0,0,0,1)]`。
- Hover 或 Active 状态通过位移和阴影收缩形成按压感，例如 `translate-x-1 translate-y-1 shadow-none`。
- 相同层级的组件必须保持边框宽度、阴影方向和偏移量一致。

### 2.2 色彩

- 使用高对比、成块的实色；主要表面以白色或浅色为主，亮黄色、绿色等作为有限的强调色。
- 同一页面只使用一组稳定的主色与强调色，不随意混用冷暖灰或多个无语义的强调色。
- 颜色必须表达明确语义，例如成功、警告、错误和当前状态；不能只依赖颜色传递信息。
- 正文、按钮文字和表单信息必须满足清晰可读的对比度。

### 2.3 排版与背景

- 标题使用粗体和紧凑层级，正文保持舒适行高；避免仅靠极大字号制造层级。
- 数字、代码和技术状态可使用等宽字体，但普通正文保持项目现有字体。
- 页面可使用细小黑色圆点组成的矩阵背景；背景不能干扰正文阅读。
- 状态标签采用粗边框、短文本和明确色彩，例如 `DONE`、`PAUSE`，同时提供中文或上下文说明。

## 3. 布局与响应式

- 页面内容使用稳定的最大宽度和水平留白；优先使用 CSS Grid 处理多列布局，避免复杂的百分比计算。
- 桌面端可以采用不对称布局，但小于 `md` 断点时必须收敛为单列，禁止横向溢出。
- 全屏区域使用 `min-h-[100dvh]`，避免移动浏览器中 `h-screen` 引发跳动。
- 控件、标题、说明和错误信息必须有稳定间距；不要用大量任意值修补对齐。
- 数据密集页面优先使用分隔线、留白和表格层级，不滥用卡片网格。

## 4. 组件与交互状态

- 优先复用 `frontend/src/components` 中已有组件；新增公共模式时再抽取组件。
- 按钮、链接、表单控件必须提供 Hover、Active、Focus Visible 和 Disabled 状态。
- 表单标签置于输入框上方，错误信息紧邻对应字段；必填、格式和提交失败原因需要明确说明。
- 异步界面必须覆盖 Loading、Empty、Error 和 Success 状态，骨架屏应贴近真实布局。
- 动画只用于解释状态或增强反馈，优先变换 `transform` 和 `opacity`，避免动画 `top`、`left`、`width`、`height`。
- 尊重 `prefers-reduced-motion`；非必要动画在减少动态效果时应关闭。

## 5. 可访问性与内容

- 所有功能必须可通过键盘完成，并提供清晰的焦点样式。
- 图标按钮必须有可访问名称；有信息意义的图片需要准确的 `alt`，纯装饰图片使用空 `alt`。
- 交互目标在触屏设备上应具有足够尺寸和间距。
- 不使用颜色作为唯一状态提示；错误、成功和警告同时提供文字或图标。
- 文案使用具体动作和结果，避免含糊的营销式表达。

## 6. 技术约束

- 当前项目使用 Next.js、React 和 Tailwind CSS；实现前先检查现有组件、`package.json` 和 Tailwind 版本。
- 不为单个视觉效果引入新的依赖。确需依赖时，先说明必要性并确认项目尚未具备等价能力。
- Client Component 只承载确实需要浏览器状态或交互的叶子组件，静态页面结构优先保持为 Server Component。
- 不编辑生成文件，不把构建产物、运行时上传文件或环境配置作为设计资源提交。

## 7. UI 变更验收清单

- [ ] 与现有 Neo-Brutalism 视觉语言一致，没有引入竞争风格。
- [ ] 信息层级、间距、对齐和阅读顺序清晰。
- [ ] 桌面端与移动端均无横向溢出或布局跳动。
- [ ] Hover、Active、Focus、Disabled、Loading、Empty 和 Error 状态完整。
- [ ] 键盘操作、焦点可见性、图片替代文本和文字对比度符合要求。
- [ ] 动画仅使用必要的 `transform`、`opacity` 等低成本属性，并支持减少动态效果。
- [ ] 已运行前端 `pnpm check` 和 `pnpm build`；若被既有错误阻断，需明确记录。
